### 1.1 原始需求复述

在已上线的「词忆 CET」四六级词汇网站中，新增一个**站内可直接打开**的竖版弹幕射击游戏《词战长空》。玩家驾驶战机守卫"词空"，每波敌机携带一个英语单词，玩家必须在敌机抵达防线前，用**正确的释义弹药**将其击落——打对敌机消散，打错敌机突进并扣血。

**核心产品命题（不可偏离）**：不是"做一个飞机大战"，而是**把背单词的动作，无缝转化为游戏的操作动作**。

- 判定必须发生在"敌机抵达前"，用**时间压力**催化记忆固化。
- 每次判定后**必须**弹出「记忆强化卡」，让"记住"这件事被看见。
- 答错**绝不结束游戏**，只扣血 + 进错词本 + 高亮正确释义。
- **成就感必须来自"我记住了"，而不是"我活得久"。这是学习工具，不是淘汰赛——任何让玩家"因为答错而想关掉页面"的设计都是失败的设计。**

## 2. 产品定义

### 2.1 Product Goals（3 个正交目标）

| # | 目标 | 说明 |
|---|------|------|
| G1 | **把背词动作转化为游戏操作** | 出题即敌机来袭、作答即开火。玩家不是为了通关而答，而是答对本身就是通关手段。 |
| G2 | **用时间压力制造深度记忆编码** | 在敌机抵达防线前作答，逼出快速音/形/义提取；每次判定后的强化卡完成"确认—巩固"闭环。 |
| G3 | **零挫败的可持续学习体验** | 答错只扣血不结束、正确释义即时高亮、错词本自动沉淀并可一键专攻。让"答错"成为学习入口而非退出理由。 |

### 2.2 成功指标（如何衡量"确实在学习"而非"只是好玩"）

**必须区分“玩得久”和“学得进”。以下指标以后者为主，前者只做体验健康度参考。**

| 类别 | 指标 | 目标值 | 为什么能证明"在学" |
|------|------|--------|-------------------|
| 学习成效（主） | 单局**新接触词汇数**（本局首次出现在词池的词数） | ≥ 8 / 局 | 说明不是只刷熟词 |
| 学习成效（主） | 单局**正确率**区间 | 60%–85% 为健康 | 过高=送分题无学习；过低=挫败 |
| 学习成效（主） | 强化卡**停留时长达标率**（≥0.8s 才算看过） | ≥ 90% | 保证强化卡真的被看到 |
| 学习成效（主） | **错词本闭环率** = 进错词本后被"连对 2 次移出"的比例 | ≥ 40% | 直接证明"记住了" |
| 学习成效（主） | 游戏后 24h 内进入 `/library` 或 `/review` 的比例 | ≥ 15% | 证明游戏能导流回正规学习 |
| 体验健康度（辅） | 单局平均时长 | 2–5 分钟 | 碎片时间可用，不失控 |
| 体验健康度（辅） | 答错后**继续本局**的比例 | ≥ 92% | 验证"不是淘汰赛"设计成立 |
| 体验健康度（辅） | 三种模式使用分布 | 无单一模式占比 > 70% | 听音/中→英未被冷落 |

> 反指标（出现即视为设计失败，需回炉）：正确答案位置可被位置记忆刷分、连续 3 局正确率 > 95%、单局答错 1 次即退出率 > 25%。

## 3. 题型模式详细规则

在设置内可切换，并提供"混合模式"（每波随机轮换三种题型，轮换时不会连续两波同一题型）。

| 模式 | 敌机气泡显示 | 玩家选择 | 训练能力 | 默认 |
|------|-------------|---------|---------|------|
| **英→中** | 英文单词（大字）+ 音标（可选） | 4 个中文释义 | 词义识别 | ✅ 默认 |
| **中→英** | 中文释义（取 `meanings[0]`） | 4 个英文单词 | 主动回忆（更难） | — |
| **听音辨词** | 仅 🔊 脉冲图标 + **不显示单词/释义** | 4 个英文单词 | 听力辨音 | — |
| **混合模式** | 以上三种每波随机轮换 | 随题型 | 综合 | — |

**通用判定规则：**

- 玩家在出题计时内选择 → 立即判定；超时未选 → 视为答错（敌机自动突进扣血），并写入错词本（超时词 = 未掌握）。
- 答对：敌机爆炸（粒子/缩放消散）、得分 +、连击 +、`correctStreak +1`。
- 答错：敌机突进至防线并闪光、战机扣血、连击清零、**正确选项立即高亮**、写入错词本、`correctStreak` 归零、`wrongCount +1`。
- 判定后无论对错，**必弹强化卡**（规格见 §5）。

**模式专属细节：**

- 听音辨词：每波出题时自动 `speak(word, settings.voice)` 播放一次；弹药区提供一个 🔊 重播按钮（不需要作答也能点，`aria-label="重播发音"`）。默认**不自动播放全局音效**，但题型本身所需发音允许自动播放（这是题面，非惊吓音效）；仍受"音效总开关"控制，关闭时以音标文本替代。
- 中→英：中文释义可能多义，取 `meanings[0]` 显示；正确答案为 `word` 原形。
- 混合模式：在同一局内轮换；若当前词已无足够干扰项可组题，则按 §4 兜底换词，不得跳过判定。

## 4. 干扰项生成规则（P0 核心，决定"像不像真题"）

每组 4 个选项 = 1 正确 + 3 干扰。生成顺序与硬约束如下：

> **前置条件**：所有候选（正确词与干扰项）都必须先通过 **§4.1 词池过滤**。

**步骤 1 · 易混词优先（`confusables`）**
- 从正确词的 `confusables` 字段解析候选（字段为字符串数组，形如 `["abundant adj. 丰富的"]`，**不是纯单词 id**）；解析方式 `split(/[\s（(]/)[0].toLowerCase()` 取首 token，再回查词池 `Map`。
- 实测解析命中率：48 条 confusable 中命中词池 **45 条**，未命中 3 条（`adsorb` / `adept` / `rise`，不在四六级大纲内）。
- **未命中时静默跳过该条，不得崩溃**；不在当前词池的同样丢弃。
- ⚠️ **`confusables` 全库仅 33 词（0.39%），覆盖率不足 1%**——此步是"锦上添花"，**不是主路径**。95% 以上的出题会直接走步骤 2。不足 3 个则进入步骤 2 补齐。

**步骤 2 · 同 tier + 同 pos 兜底（100% 覆盖的主路径）**
- 从词池中筛：`tier` 相同、`pos` 匹配、且 `id !== 正确词`。
- **`pos` 必须当自由字符串处理（严禁当枚举）**——全库有 22 种取值含复合词性（`adj./n.`、`n./v.`）。匹配顺序：**精确相等 → 取 `/` 前第一段的主词性相同 → 忽略 pos 维度**。
- ⚠️ `n.` 占全库 39.9%，**只靠"同 pos"会引入大量同类噪音**，必须叠加步骤 3 的语义过滤。
- 对每个候选做**语义重叠过滤**（步骤 3）。

**步骤 3 · 语义重叠过滤（严禁两个选项都算对）**
- 若某干扰项的任一 `meanings` 与正确答案的任一 `meanings` **存在相同中文子串**（长度 ≥ 2 的连续中文匹配），则**丢弃该干扰项并重抽**。
- 选项文案本身也只展示 `meanings[0]`，因此额外校验：干扰项 `meanings[0]` 不得等于/包含正确答案 `meanings[0]`。
- 过滤后候选不足时，放宽到"同 tier 任意 pos"，仍不足则放宽到"任意 tier"，每级放宽都必须重新做语义重叠过滤。

**步骤 4 · 高频词优先保留（口径 = `isHot`，即 S∨A）**
- 在候选池中，热度更高的词更"像"正确答案、更难猜，**优先纳入干扰项**。
- ⚠️ **判据必须用 `heatGrade(fs, tier)` + `isHot()`，不得自建阈值**；且**不得用"S 档"筛词**——实测 **S 档（fs≥90）全库仅 1 个词**，按 S 筛会得到空集。**"高频" = A 档及以上（fs ≥ 78）**：按**原始记录口径** 2817 词，按**去重后词池口径** **2044 词**。
- 排序策略：`isHot` 优先 → 再按 `fs` 降序 → 最后 `shuffle` 打破并列。

**步骤 5 · 位置随机且不连续重复**
- 每局选项顺序 `shuffle`。
- 同一单词的**正确项位置**不得与上一次出现时相同（用会话内 `Map<wordId, lastCorrectIndex>` 记录，若随机结果相同则重排）。
- 同一局内相邻两波的正确项位置尽量不同（软约束，能避免则避免）。

**兜底**：若经所有放宽仍凑不满 3 个干扰项（词池过小/极端情形），允许不足 4 选项，但**不得低于 2 个选项**，并记录一条 warn 日志；正确项始终存在。

**「专攻错词」模式特例**：词池 = 错词本中的词。若错词 < 4，干扰项从全量词池按上述规则补齐（保证可选择）。

### 4.1 词池过滤规则（P0 必做 · 保证题目质量）

**背景（实测）**：`fs` 最高的词里混有英语功能词——

```
fs Top12 实测：account(90) access(89) challenge(89) assume(88) i(88)
              available(87) claim(87) a(87) and(87) be(87) can(87) do(87)
fs≥80 的三字母词：and can for not all but get her him his how let now
                one out any day god man off our put say way may new old own
```

让玩家做「"and" 的中文释义」四选一，**既是送分题更是垃圾题**，会直接破坏 §2.2「正确率 60–85% 才健康」的目标。**必须建立词池过滤，作为所有出题与干扰项的共同前置条件。**

**过滤规则（判据分两级，双保险）：**

| 级别 | 判据 | 说明 |
|------|------|------|
| **主判据（黑名单）** | 剔除**纯功能词**：`art.` 冠词、`pron.` 代词、`prep.` 介词、`conj.` 连词、`aux.` 助动词、`det.` 限定词、`int.` 感叹词、`num.` 数词 —— 这类词无实义、不可考辨析 | 按 `pos` 精确/前缀匹配剔除 |
| **主判据（显式名单）** | 显式黑名单（实测全库仅 23 个 `len≤2` 词，且 Top 高频中仅 `i/a/and/be/of/can/do` 等为功能词）：<br>`a ad as at ax be by do go he hi i if in it me my no of oh on or ox` | 直接 `Set` 命中即剔除 |
| **副判据（长度兜底）** | 剔除 `word.length <= 2` | 作为安全网，防止新增分片引入未列入黑名单的超短词 |
| **保护规则（防误杀）** | **`len >= 3` 的词一律不得因长度被剔除** | 实测 `len==3` 共 243 词，含 `aim / bud / jam / jet / aid / bad / big / car / job / new / old` 等**合法考点词**，误杀会掏空题库 |

**边界要求：**

- 过滤**只作用于游戏词池**（`useGameWords` 的派生结果），**不得改动 `useWords()` 返回的全局 Map**，也不得影响词库页 / 复习 / 学习模块。
- **过滤后词池规模实测：保留 6537 词，剔除 130 词**（基数为**去重后词池 6667**，见 §1.2 口径说明）。
- 剔除的 `pos` 分布（实测）：`prep.` 42、`pron.` 31、`num.` 21、`conj.` 15、`det.` 7、`int.` 6，以及因黑名单/短词命中的 `n.` 3、`v.` 2、`art.` 1、`aux.` 1、`adv.` 1。
- 过滤后词池规模需 ≥ 20（实测 **6537**，远高于此阈值）；若异常导致过小，**放弃过滤并记录 warn**，保证游戏可玩性优先。
- ⚠️ **被剔除的"长词"属刻意取舍，勿误判为 bug**：`despite / amongst / beneath / throughout / via / regarding / provided` 是**靠 `pos` 判据（介词/连词）剔除，不是靠长度**。它们作为四选一释义题确实出不了好题。
- 「专攻错词」模式若错词本中命中被过滤词（历史数据），**同样执行过滤**并提示"该词不适合出题已跳过"，不得因过滤导致空局。

**验收判据**：随机抽 50 个出题词，**不得出现 `pos` 为功能词性或 `len ≤ 2` 的词**；且抽查 `abandon / assess / available / access / challenge / aim / job / new / old / plan` —— **全部必须保留可出题**（反误杀，已实测通过）；功能词 `and(conj.) / be(len2) / i(pron.) / a(art.)` —— **必须全部被剔除**（已实测通过）。

## 6. 错词本数据结构与生命周期

**存储键**：`cetyi.game.wrongbook.v1`（严格遵守 `cetyi.game.*` 命名空间，不得触碰既有键）

**数据结构：**

```ts
type WrongBook = Record<string, WrongWordEntry>; // key = wordId（小写拼写）

interface WrongWordEntry {
  word: string;         // 显示用原形
  wrongCount: number;   // 累计答错/超时次数
  lastWrongAt: number;  // 最近一次答错时间戳（ms）
  correctStreak: number;// 进入错词本后的连续答对次数
}
```

**生命周期：**

| 事件 | 动作 |
|------|------|
| 答错 / 超时 | `wrongCount += 1`，`correctStreak = 0`，`lastWrongAt = now`；不存在则新建条目 |
| 在错词本中的词**答对** | `correctStreak += 1` |
| `correctStreak >= 2` | **从错词本移除**（体现"记住了"） |
| 「专攻错词」模式 | 词池 = 错词本现存词；答对同样累计 `correctStreak`，连对 2 次即移出 |
| 读取 | 每次进入游戏 / 结算时读一次；写入后立即持久化（自带 try/catch，存储满静默失败） |
| 损坏兜底 | JSON 解析失败或结构非法 → 视为空错词本，**不抛错、不清空其它键** |

**与站点 SRS 的关系（✅ 已定调：一律只读，不联动）：**

> **结论（主理人技术评估确认）**：游戏对 `cetyi.v1` **只读，不写入**。原 P1-4「SRS 轻度复习联动」**已否决**，降级为 P2「明确不做」。

**否决理由（`src/lib/store.ts:100` `grade()` 副作用链实测）**：该函数副作用远超"记一次复习"：

| # | 副作用 | 后果 |

## 8. 扣血公式（已确认策略：fs 越高，答错扣血越多）

**策略（写入代码注释必须说明理由）**：`fs` 越高的词越是真题高频必考词，答错说明"最该掌握的词没掌握"；用更重的扣血把玩家注意力拉回高频词，这比"保护信心"更符合应试提分目标。

**公式**（`fs` 取值范围以**实测 16–90** 为准，见 §1.2；median=55）：

```
damage = clamp( round( 1 + 2 * (fs / 100) ), 1, 3 )   // 四舍五入
```

**换算说明（与公式严格一致，请勿另立一套阈值）**：`1 + 2·fs/100` 的值为：

| `1 + 2·fs/100` 区间 | 对应 `fs` | 四舍五入后 damage | 实测词数 | 实测占比 |
|--------------------|----------|------------------|---------|---------|
| < 1.5 | `fs ≤ 24`（即 **fs < 25**） | **1** | 410 | 4.8% |
| 1.5 ~ 2.5（不含 2.5） | `25 ≤ fs ≤ 74` | **2** | 4643 | 54.3% |
| ≥ 2.5 | `fs ≥ 75` | **3** | 3490 | 40.9% |

> ⚠️ **v1.0 勘误**：上一版把 `fs ≥ 75` 整段写作 3 点却未说明公式在 `fs=75` 处恰为临界值，导致"表与公式自相矛盾"的观感。**以本表为准**：`fs=75` 时 `1+2×0.75 = 2.5`，四舍五入为 **3 点**，是 3 点档的**下边界**；`fs=74` → `2.48` → 2 点。边界严格为 **`fs < 25` → 1、`25 ≤ fs < 75` → 2、`fs ≥ 75` → 3**。
> 另注：Python 内置 `round()` 为银行家舍入（`round(2.5)==2`），实现时**必须用 `Math.round`（JS 为 half-up，`Math.round(2.5)==3`）**，勿混用，否则 `fs=75` 会掉档。

**实际伤害分布（实测落档，非理论值）**：1 点仅占 **4.8%**（约 410 词），2 点 **54.3%**，3 点 **40.9%**。即**约 95% 的词答错都会扣 2~3 点**，梯度集中在中高档——符合"高频必考词答错代价重"的设计意图。

| `fs` 情形 | damage | 说明 |
|-----------|--------|------|
| `fs < 25` | 1 | 低频长尾词（答错惩罚最轻），**仅约 5% 的词** |
| `25 ≤ fs < 75` | 2 | 中频词（主力档位，约 54%） |
| `fs ≥ 75` | 3 | 高频必考词（答错惩罚最重，约 41%） |
| `fs` 缺失/非法 | 2 | 兜底按中频处理 |

**边界与容错：**
- 生命值下限 0，`hp = max(0, hp - damage)`；`hp` 无上限（补给可加至 5）。
- 同一局内同一词重复答错仍照常扣血（不因已错过而豁免）。
- **仅答错/超时扣血**；答对不加血（补给道具除外，见 P1）。

| 鼠标 | 移动鼠标左右跟随 | 点击弹药按钮 |
| 触摸 | 拖动战机左右移动（`touchmove` 调 `preventDefault` 阻止页面滚动） | 点击弹药按钮 |
| 键盘 | `←` / `→` 方向键左右移动 | `1` / `2` / `3` / `4` 直接选择对应弹药；`Enter` 激活焦点按钮 |

### 10.2 硬性无障碍要求

| 项 | 规格 |
|----|------|
| 按钮热区 | 移动端所有可点元素 ≥ **44×44 px** |
| `aria-label` | 所有按钮必须带语义化 `aria-label`（暂停 / 发音 / 重播 / 各弹药 / 结束面板按钮） |
| 键盘可达 | `Tab` 可遍历全部可交互元素，`Enter` / `Space` 可激活 |
| reduce-motion | 尊重 `prefers-reduced-motion: reduce`：关闭抖动/粒子/屏幕震动，仅保留必要淡入淡出；游戏内提供"减少动效"开关 |
| 三重编码 | 正确/错误状态必须**同时**用 **颜色 + 图标 + 文字** 表达（如：绿 + ✓ + "正确"；红 + ✕ + "正确释义是…"），**严禁只靠颜色**（色盲友好） |
| 音量 | 音效开关默认**静音友好**（不自动播放惊吓性音效）；发音属题面能力，受总开关控制 |
| 对比度 | 亮/暗主题下 HUD、弹药按钮、强化卡文字对比度需可读（复用站点 CSS 变量，不硬编码色值） |
| 焦点可见 | 键盘焦点有可见描边（复用站点 `--ring`） |

### 10.3 主题映射（禁止硬编码色值）

| 用途 | CSS 变量 |
|------|---------|
| 游戏画布背景 / 星空 | `hsl(var(--background))` + `--grad-a/--grad-b/--grad-c` 点缀 |
| HUD / 弹药面板 / 强化卡底 | `hsl(var(--card))` + `1px solid hsl(var(--border))`（可用 `.glass-card`） |
| 主色调（战机 / 正确态 / 高亮） | `hsl(var(--primary))`，配合 `.neon-text` / `.glow-ring` |
| 答错态 / 受伤 | `hsl(var(--destructive))` + `.animate-shake` |
| 次要文字 | `hsl(var(--muted-foreground))` |
| 单词展示 | `.font-word`（词典衬线字） |
| iOS 底部安全区 | `.safe-bottom` |
